# 要件定義書

## はじめに

本システムは、麻雀の半荘ごとのスコアを「部屋」単位で管理し、最終的な合計スコアを計算する戦績管理システムである。各ユーザーは自分のスマートフォンから自分のスコアのみを入力し、部屋全体のスコアボードで全メンバーの累計スコアを確認できる。各半荘は3人または4人でプレイし、スコアはウマ・オカ・ヤキトリ・チップを含めて計算され、Firebase Firestoreに永続化される。

## 用語集

- **システム**: 麻雀戦績管理システム
- **部屋**: 複数の半荘をまとめ、スコアボードを表示する単位
- **メンバー**: 部屋に参加し、半荘をプレイするユーザー
- **半荘**: 3人または4人で行われる麻雀の1ゲーム
- **得点**: 半荘終了時の各プレイヤーの点数（素点）
- **スコア**: ウマ・オカ・ヤキトリ・チップを含めて計算された最終的な得点
- **ウマ**: 順位に応じた点数調整
- **オカ**: 持ち点からの差分を基にした点数計算
- **ヤキトリ**: その半荘で一度も上がっていない状態
- **チップ**: 役満や特定の役で授受される追加得点要素
- **Firestore**: Firebase提供のNoSQLクラウドデータベース
- **入力中**: 半荘が作成され、各プレイヤーがスコアを入力している状態
- **確定**: 半荘のスコアが検証され、変更不可能になった状態

## 要件

### 要件1: 部屋の作成と管理

**ユーザーストーリー:** ユーザーとして、麻雀の戦績を記録するための部屋を作成し管理したい。そうすることで、複数のメンバーと半荘の記録を一元管理できる。

#### 受入基準

1. WHEN ユーザーが部屋作成を要求する THEN システムは現在の年月日時分（yyyy/MM/dd HH:mm形式）を部屋名として新しい部屋を作成しなければならない
2. WHEN 部屋が作成される THEN システムは部屋の一意な識別子を生成しFirestoreに保存しなければならない
3. WHEN 部屋が作成される THEN システムはデフォルトの部屋設定を初期化し、自動的に1回目の半荘を開始しなければならない
4. WHEN ユーザーが部屋一覧を表示する THEN システムは作成日時の降順で部屋を表示しなければならない
5. WHEN ユーザーが部屋一覧を表示する THEN システムは各部屋のメンバー名を表示しなければならない
6. WHEN ユーザーが部屋を選択する THEN システムはその部屋の詳細情報を表示しなければならない
7. WHEN ユーザーが部屋削除ボタンを押下する THEN システムは確認メッセージを表示しなければならない
8. WHEN ユーザーが削除を確認する THEN システムは部屋とその関連データをFirestoreから削除しなければならない

### 要件2: メンバー管理

**ユーザーストーリー:** メンバーとして、部屋に入室し自分の名前を設定したい。そうすることで、部屋内で自分を識別できる。

#### 受入基準

1. WHEN メンバーが初めて部屋に入室する THEN システムは名前の入力を要求しなければならない
2. WHEN メンバーが名前を入力する THEN システムは一意なユーザーIDを生成しクッキーに保存しなければならない
3. WHEN メンバーが同じ部屋に再度入室する THEN システムはクッキーから部屋ごとの名前を読み取り名前入力をスキップしなければならない
4. WHEN メンバーが異なる部屋に入室する THEN システムは新しい名前の入力を要求しなければならない
5. WHEN メンバーが部屋に入室する THEN システムはメンバー情報をFirestoreに保存しなければならない

### 要件3: 半荘の作成と記録

**ユーザーストーリー:** ユーザーとして、新しい半荘を開始し自分の得点を入力したい。そうすることで、スムーズに戦績を記録できる。

#### 受入基準

1. WHEN ユーザーが新しい半荘を開始する THEN システムは新しい半荘を「入力中」状態で作成しなければならない
2. WHEN 新しい半荘が作成される THEN システムは前の半荘を検証し確定しなければならない
3. WHEN 前の半荘の検証が失敗する THEN システムはエラーを表示し新しい半荘の作成を拒否しなければならない
4. WHEN ユーザーが得点を入力する THEN システムは数値の妥当性を検証しなければならない
5. WHEN ユーザーが得点を入力する THEN システムは得点が100の倍数であることを検証しなければならない
6. WHEN ユーザーが得点を入力する THEN システムは入力をFirestoreに即座に保存しなければならない
7. WHEN 半荘が「入力中」状態である THEN システムはメンバーによる得点の追加・修正を許可しなければならない

### 要件4: 半荘の検証と確定

**ユーザーストーリー:** システム管理者として、半荘のデータが正しいことを自動検証したい。そうすることで、不正なデータの蓄積を防げる。

#### 受入基準

1. WHEN 半荘が検証される THEN システムは入力数が3人または4人であることを確認しなければならない
2. WHEN 半荘が検証される THEN システムは得点合計が正しいことを確認しなければならない（3人:105000点、4人:100000点）
3. WHEN 半荘が検証される THEN システムは全員が得点を入力済みであることを確認しなければならない
4. WHEN 検証が成功する THEN システムは半荘を「確定」状態にし、得点の降順で順位を計算しなければならない
5. WHEN 半荘が「確定」状態である THEN システムは得点の変更を拒否しなければならない
6. WHEN 複数のプレイヤーが同点である THEN システムは同順位として扱わなければならない

### 要件5: スコア計算

**ユーザーストーリー:** ユーザーとして、ウマ・オカ・ヤキトリ・チップを含めた正確なスコアを確認したい。そうすることで、公平な戦績評価ができる。

#### 受入基準

1. WHEN 半荘が確定される THEN システムは部屋設定の返し点を基準にオカを計算しなければならない
2. WHEN 半荘が確定される THEN システムは部屋設定のウマ値に応じてウマを加算しなければならない
3. WHEN スコアが計算される THEN システムは（得点 - 返し点）/ 1000 + ウマの式でスコアを算出しなければならない
4. WHEN ヤキトリ設定がONである THEN システムはメンバーがスコア入力時にヤキトリを申告できるようにしなければならない
5. WHEN 半荘が確定される THEN システムはヤキトリの人からヤキトリでない人へペナルティスコアを均等割りで支払わなければならない
6. WHEN チップ設定がONである THEN システムはチップの授受を記録しスコアに反映しなければならない
7. WHEN 半荘が確定される THEN システムは計算されたスコアを半荘記録に保存しなければならない

### 要件6: スコアボードの表示

**ユーザーストーリー:** ユーザーとして、麻雀の一般的な得点記録帳の形式で全ての半荘記録とメンバーのスコアを確認したい。そうすることで、各半荘の詳細と累計スコアを一目で把握できる。

#### 受入基準

1. WHEN ユーザーが部屋のスコアボードを表示する THEN システムは縦軸に半荘回数、横軸にメンバー名を配置した表形式で表示しなければならない
2. WHEN スコアボードが表示される THEN システムは各メンバーの列に「-」列と「+」列を分けて表示しなければならない
3. WHEN スコアボードのセルが表示される THEN システムは「-」列に負のスコア、「+」列に正のスコアを表示しなければならない
4. WHEN ユーザーがスコアセルをクリックする THEN システムはスコア詳細モーダルを表示しなければならない
5. WHEN スコア詳細モーダルが表示される THEN システムは得点・スコア・ウマ・ヤキトリ・チップの内訳を表示しなければならない
6. WHEN スコアボードが表示される THEN システムは各メンバーの累計スコアを最下行に表示しなければならない
7. WHEN 合計スコアが計算される THEN システムはそのメンバーが参加した確定済み半荘のスコアのみを合算しなければならない
8. WHEN スコアボードが表示される THEN システムはスコアの降順でメンバーを並べなければならない
9. WHEN 半荘が「入力中」状態である THEN システムはその行を視覚的に区別して表示しなければならない
10. THE システムはスコアボードをリアルタイムで更新しなければならない

### 要件7: データの永続化

**ユーザーストーリー:** システム管理者として、全てのデータをFirestoreに保存したい。そうすることで、データの永続性と複数デバイスからのアクセスを実現できる。

#### 受入基準

1. WHEN 部屋が作成される THEN システムは部屋データをFirestoreのroomsコレクションに保存しなければならない
2. WHEN メンバーが追加される THEN システムはメンバーデータをFirestoreに保存しなければならない
3. WHEN 半荘が記録される THEN システムは半荘データをFirestoreに保存しなければならない
4. WHEN データ保存に失敗する THEN システムはエラーメッセージを表示しユーザーに通知しなければならない
5. THE システムはFirestoreとの通信エラーを適切にハンドリングしなければならない

### 要件8: ユーザー識別とスコア入力

**ユーザーストーリー:** メンバーとして、自分のスマートフォンから自分のスコアのみを入力したい。そうすることで、各自が独立してスコアを記録できる。

#### 受入基準

1. WHEN メンバーが初めて名前を設定する THEN システムは一意なユーザーIDを生成しなければならない
2. WHEN ユーザーIDが生成される THEN システムはIDをブラウザのクッキーに保存しなければならない
3. WHEN メンバーが部屋に入室する THEN システムはクッキーからユーザーIDと部屋ごとの名前を読み取らなければならない
4. WHEN メンバーが半荘のスコア入力画面を開く THEN システムは自分の得点入力欄のみを表示しなければならない
5. WHEN メンバーが得点を入力する THEN システムは自分のメンバーIDに紐づけて保存しなければならない
6. WHEN メンバーが「入力中」の半荘を表示する THEN システムは他のメンバーの入力状況をリアルタイムで表示しなければならない

### 要件9: 部屋設定のカスタマイズ

**ユーザーストーリー:** ユーザーとして、部屋ごとにルール設定をカスタマイズしたい。そうすることで、様々な麻雀ルールに対応できる。

#### 受入基準

1. WHEN ユーザーが部屋設定を編集する THEN システムはウマの1-4位間および2-3位間の値を個別に設定可能にしなければならない
2. WHEN ユーザーがゴットーボタンを押下する THEN システムはウマをトップ-ビリ間10、2-3位間5に設定しなければならない
3. WHEN ユーザーがワンツーボタンを押下する THEN システムはウマをトップ-ビリ間20、2-3位間10に設定しなければならない
4. WHEN ユーザーがオカ設定を編集する THEN システムは開始点と返し点を個別に設定可能にしなければならない
5. WHEN ユーザーがヤキトリ設定を編集する THEN システムはON/OFFの切り替えを可能にしなければならない
6. WHEN ユーザーがチップ設定を編集する THEN システムはON/OFFの切り替えを可能にしなければならない
7. WHEN 部屋設定が変更される THEN システムは変更内容をFirestoreに保存しなければならない
8. THE システムは部屋設定の変更を既存の半荘記録に遡及適用してはならない
